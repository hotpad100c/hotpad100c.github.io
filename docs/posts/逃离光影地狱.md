# 如何逃离光影包地狱

## 0. 前置知识

本教程假设你已经：

- 会写 Fabric 模组；
- **基本上**知道什么是 **帧缓冲 / 渲染目标（RenderTarget）**、**深度缓冲**、**深度测试**。如果不熟，[LearnOpenGL](https://learnopengl-cn.github.io/) 可以帮到你。

此外需要注意的是，**Minecraft 从 26.2 起使用反向深度（Reversed-Z）**：

| | 近处 | 远处 |
|---|---|---|
| 26.2 及以后 | 1.0 | 0.0 |
| 26.2 以前 | 0.0 | 1.0 |

为了让着色器在两种约定下都适用且容易阅读，参考实现引入了一个叫 **接近度** 的概念，越大越近，`closeness()` 把深度值换算成接近度，`depthOf()` 是反向换算。

```glsl
#ifdef STANDARD_DEPTH          // 旧版本：近 = 0，远 = 1
float closeness(float depth) { return 1.0 - depth; }
float depthOf(float closeness) { return 1.0 - closeness; }
#else                          // 26.2+：近 = 1，远 = 0
float closeness(float depth) { return depth; }
float depthOf(float closeness) { return closeness; }
#endif
```

后文所有深度比较**都用接近度来写**，"A 比 B 更近"就等于 `closeness(A) > closeness(B)`；
往深度缓冲里**写**值时，我们先算接近度，再用 `depthOf()` 换算。

## 1. Iris 如何肘击你的渲染

```
Iris 的一帧
 ├─ begin* 全屏 pass            beginLevelRendering() -> beginRenderer.renderAll()
 ├─ shadow pass                 从太阳视角再画一遍世界，生成阴影图
 │                              └─ prepare* 全屏 pass（紧接在 shadow 之后）
 ├─ gbuffers 阶段               画不透明地形、实体、天气……
 │      原版渲染管线在 GlDevice.getOrCompilePipeline 处被替换成
 │      光影包的 gbuffers_* 程序
 ├─ beginHand()                 复制深度到 depthtex2（"不含手的非半透明深度"）
 ├─ 画第一人称手（不透明部分）  HandRenderer.renderSolid()
 ├─ beginTranslucents()         复制深度到 depthtex1，然后运行 deferred* 全屏 pass
 ├─ 画半透明（水、玻璃……）      TRANSLUCENT_TERRAIN -> gbuffers_water 等
 ├─ 画手的半透明部分            HandRenderer.renderTranslucent()（帧末注入点）
 ├─ composite* -> final          帧末全屏后处理，结果写回主渲染目标
 └─ LevelRenderer.renderLevel 结束
```

你的渲染如果混在 gbuffers 阶段里，就会被 Iris 改动三处：

1. **着色器替换**：Iris 在 `GlDevice.getOrCompilePipeline` 统一拦截，把原版 `RenderPipeline`（半透明地形、线条等）换成光影包对应的 `gbuffers_*` 程序。例如 `TRANSLUCENT_TERRAIN → gbuffers_water`、`LINES → gbuffers_line`。这些程序按它理解的"地形""方块实体"着色，你设定的颜色不会原样保留。未被登记的自定义 pipeline 会走 `findBestMatch` 猜测匹配，你猜准不准？
2. **顶点格式扩展**：光影包的着色器需要额外的顶点属性（`mc_Entity`、`mc_midTexCoord`、`at_tangent`、`at_midBlock`），Iris 在 `BufferBuilder` 构造时把 BLOCK / ENTITY / POSITION_COLOR_TEX_LIGHTMAP 格式透明加宽，并在写入顶点时自动回填这些属性。走 `BufferBuilder` 的代码无需改动；但如果你提前构建了顶点，或者自行构造 `VertexFormat`，写入布局与着色器期望的加宽布局不匹配，场面会像星际穿越的虫洞内部一样灿烂，或因属性缺失报错。
3. **后处理**：就算躲过前两处，你画进去的颜色还是会被 deferred、composite、final 阶段的泛光、色调映射、雾等搅和一遍。

事实上，若不仔细适配，没几个自定义渲染能活着走出来。有时甚至包括Minecraft自己的渲染管线。

## 2.建设应急通道

值得庆幸的是，Iris提供一些方法来解除部分影响。Iris 用 `net.irisshaders.iris.vertices.ImmediateState` 里的几个静态字段决定要不要插手一次绘制。

| 开关 | 类型 | 平时的值 | 我们期望的值| 效果 |
|---|---|---|---|---|
| `bypass` | `static boolean` | `false` | `true` | Iris 不再把原版渲染管线替换成光影包的程序。|
| `skipExtension` | `ThreadLocal<Boolean>`，只对当前线程有效 | `false` | `true` | **新建的** `BufferBuilder` 和原版管线都保持原版顶点格式。但不约束通过 `RenderType` 的替换。 |
| `isRenderingLevel` | `static boolean` | 由 Iris 在 `LevelRenderer.render` 期间置为 `true`，结束后置回 `false` | 临时设为 `false` | 上面两个开关只管各自那一部分，这个开关影响较大，它一次关掉 Iris 针对"正在渲染世界"的全部处理。停止所有路径（包括 `RenderType`）上的顶点格式加宽。 |

值得注意的是，**`skipExtension` 只对当前线程有效。** 它是 `ThreadLocal`，在渲染线程上设置它，影响不到别的线程。所以当你在其他线程上构建网格时，要在那个线程里另外设置一次。

但只拨这三个开关是不够的：开关挡不住后处理。 只要画进主目标，光影的泛光、色调、雾等照样会作用在你的东西上。而在高版本的 Submit 系统里，提交、生成顶点、绘制是分开进行的，入侵它并给你的东西开特例也很不方便。这同样把你置于顶点格式不匹配的风险之中。

实际上，我们希望的是一个尽可能与Iris周期互不干扰的迷你渲染周期：

1. 准备一个独立的 颜色+深度 RenderTarget（渲染目标），把你的所有绘制都重定向进去。
2. 开启一个独立的绘制周期，开始前后改写 Iris 的三个开关 `bypass`、`skipExtension`、`isRenderingLevel`，阻止它着色器并加宽顶点格式。
3. 把你的私货在这个周期里画完。
4. 在 Iris 把整帧都画完之后，把带着我们私货的渲染目标**按深度**合并回主目标。
